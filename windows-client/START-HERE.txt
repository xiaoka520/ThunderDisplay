ThunderDisplay 0.8.1 · Windows 图形客户端 / Windows GUI client

1. 最新构建为 0.8.1。双击 ThunderDisplay-GUI-0.8.1-x64.exe；中文 / English / 跟随系统。
   Caps Lock 修复只需更新 Windows，兼容 Mac 0.8.0，无需重新授权或安装开机组件。
2. 填写 Mac 网桥 IPv4 或留空自动发现；配对码默认关闭。
3. 显示模式为“自动 / 自定义”；帧率由两端屏幕协商，上限240，目标不等于实测。
   自动模式默认保留 Mac HiDPI 捕获源像素。2048×1280逻辑桌面可对应4096×2560渲染像素。
4. 自定义码率默认上限20000 Mbps（20 Gbps），以64位协商，避免溢出；需要新Mac。
   自动采用较低压缩，推荐160–1000 Mbps；4096×2560@60 Hz HEVC约570 Mbps。目标不是恒定输出，网桥上限不等于硬件编码器输出能力。
   编码器拒绝超高目标时检测其接受范围，诊断明确显示请求 / 实际接受目标，避免连接失败。
5. “本地指针 · macOS 原生”默认关闭，连接前开启。Mac 视频从首帧起隐藏指针，Windows 本地显示。
   动态同步Mac系统原始指针形状 / 隐藏状态 / 热点，按Windows DPI缩放，不能再乘Mac HiDPI比例。
   不手绘、不靠快捷键猜截屏状态；Mac系统不提供读取接口时保留视频指针。修改开关需重连。
6. 两端跟随系统深浅色实时变化。Windows 使用原生标题栏 / 控件主题，并保留系统高对比度。
7. 删除“缩放与边缘”和“1:1 原始像素显示”控件。保持完整桌面比例及不锐化的高质量GPU缩放。
   保留HiDPI源像素选项；删除控件不改变编码质量。不同面板尺寸仍需要缩放，4:2:0仍损失彩色细字。
8. 剪贴板支持文字（64 KiB UTF-8）与图片（PNG 32 MiB、最多1600万像素、单边8192）。
   两端开启后只同步新复制的内容，抑制回传。兼容Mac TIFF与Windows PNG / DIB / Bitmap，不传文件。
9. Ctrl+Alt+Enter 全屏；可自定义，不使用F11。Ctrl+Alt+Shift+Esc释放/恢复输入。
   全屏捕获时Windows快捷键交给Mac，Ctrl+Shift+Esc仍打开任务管理器，Ctrl+Alt+Del由系统处理。
   Caps Lock 同时更新 Windows 大小写状态与键盘指示灯，并传给 Mac；切回远程窗口或恢复输入时重新读取本地状态。
10. 色深为自动 / 8-bit SDR / 10-bit SDR；新版两端为sRGB SDR / BT.709矩阵 / 4:2:0，未实现HDR/P3/4:4:4/音频。
11. Mac设置可启用“随系统启动”，安装独立系统守护进程与LoginWindow图形会话组件，需管理员批准。
    登录前组件先检查真实画面和输入授权，通过后接受连接，用户登录后桌面主机接管。
    若系统拒绝权限，客户端显示登录界面捕获/输入不可用；仅安装成功不代表已验证登录前远控。FileVault开机解锁不支持。

Windows 10 1703+ / Windows 11 x64；需Media Foundation / D3D11，Windows N需媒体组件。
保留licenses目录。构建与协议/原生Mac测试通过，ROG原生主题、动态指针、GPU和两机图片粘贴待实机验收。

Latest build: 0.8.1. Run the GUI EXE; pairing is optional on the bridge.
The Caps Lock fix only requires the Windows update and is compatible with Mac 0.8.0.
Caps Lock now also updates the Windows toggle state/keyboard LED; refocusing the display or recapturing input resynchronizes local state.
Auto preserves Mac HiDPI source pixels. Custom changes resolution/bitrate; FPS follows detected displays.
The bitrate ceiling is 20000 Mbps (20 Gbps), using 64-bit negotiation. Auto uses lighter compression at 160–1000 Mbps (4096×2560@60 Hz HEVC: 570 Mbps).
Hardware rejection of an ultra-high target triggers range detection; diagnostics report the actual accepted target.
This is not a measured Thunderbolt throughput or a promise of constant 20 Gbps video output.
Optional local cursor mode streams the Mac system's real cursor pixels, visibility and hotspot, scaled once to Windows DPI.
Both UIs follow system dark/light mode. Windows uses native control/title themes and system high contrast.
Scaling/edge and pixel-exact GUI controls were removed; full desktop aspect-fit and high-quality unsharpened scaling remain.
Clipboard sync now supports new copied text (64 KiB) and PNG images (32 MiB / 16M pixels / 8192 side), with native TIFF/DIB conversion.
No existing clipboard content is exported on connect. File transfer is not implemented.
Mac settings install a system discovery daemon and a separate LoginWindow graphics agent with administrator authentication.
Before login, the agent verifies an actual frame and event-post authorization before serving; the desktop host takes over after login.
Installation alone does not establish working pre-login control. Permission failures are reported explicitly. FileVault preboot is unsupported.
Ctrl+Alt+Enter toggles fullscreen; customize it in settings. Task Manager shortcuts remain available.
Updated platforms use sRGB SDR with a BT.709 YCbCr matrix and 8/10-bit 4:2:0. Older hosts retain the legacy BT.709 path. HDR/P3/4:4:4/audio remain unimplemented.
Crosscompiled and checked; native Windows themes, cursor behavior, GPU and dual-platform image paste still require the ROG.

0.7.6：两端更新并重连后，连接诊断应显示sRGB SDR / BT.709矩阵、显式sRGB转换。自动启用，无需调整饱和度或Gamma。旧端或GPU不支持时诊断明确提示兼容色彩；P3/HDR色域仍未实现。

自动连接 / 断线恢复每轮最多10分钟、150次尝试，显示当前次数/150。超限后点击连接手动重试。
Mac 端默认“保持 Mac 可连接”，防止系统自动睡眠。雷雳不支持网络唤醒；手动睡眠后需先唤醒 Mac，主机会自动恢复。
控制通道建立不代表画面恢复；首帧成功显示后才显示已连接。视频持续中断会清除旧画面并重连。

0.7.6：动态本地指针优先使用 Mac 系统提供的高密度原图；Windows 按显示器 DPI 只缩放一次，保留原生尺寸和点击热点。两端需同时更新。

0.8.0：本地指针按 Windows 当前显示缩放自动选择 macOS 原生倍率图；存在对应倍率时直接显示原像素，移动到不同缩放的显示器会自动切换。两端需同时更新。
