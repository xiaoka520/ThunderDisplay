# ThunderDisplay

为 **Mac → 雷雳网桥 → Windows** 编写的本地远程显示器。

macOS 使用 Swift / ScreenCaptureKit / VideoToolbox；Windows 使用 C++17 / Media Foundation / Direct3D 11。
运行不依赖互联网、云账户、Moonlight、Sunshine 或第三方视频库。

## 当前实现

- macOS 全屏捕获；可选 Windows 本地显示 macOS 当前系统指针，动态同步形状、隐藏状态与原生点击热点，串流不重复绘制指针。
- HEVC Main / Main10 / H.264 High 硬件编码，8 / 10-bit 4:2:0，sRGB SDR（旧端 BT.709 兼容）；禁止 B 帧，实时编码，0.5 秒 GOP。
- 可选无压缩 10 位：保留源像素与 10-bit SDR 4:2:0，跳过 VideoToolbox 压缩和 Windows 视频解码；两端 0.8.25 仅传送逐字节变化的区域，Windows 还原完整图像后上传 GPU。帧率按两端显示器协商（程序最高 240），保留源像素与全部十位值；全屏每帧全变时，4096×2560 / 60 fps 仍需约 9.4 Gbps。
- 默认自动协商：检测 Mac 源渲染像素与 Windows 显示器原生尺寸 / 最大可用刷新率，保留源比例、避免放大，自动选择高码率。手动支持 1–240 FPS。
- TCP 配置、可选配对验证、心跳、键鼠；编码视频使用 UDP Annex B，单包最多 1200 字节，无压缩视频使用独立 TCP 连接。
- Windows D3D11 硬件解码和 GPU 色彩转换，保留宽高比，全屏、窗口缩放。
- 全屏捕获时 Win → Command、Alt → Option、Ctrl → Control；鼠标移动、三键、拖动、双向滚轮。
- Mac 多屏鼠标：TD 前台无边框全屏时，按照 macOS 屏幕排列跨屏移动、点击和拖动，实体屏与虚拟屏共用同一规则；窗口模式使用当前画面的位置映射，鼠标可离开 TD 回到 Windows。捕获画面保持选定屏幕；新端独立同步 Mac 原生指针形状与全局位置，离开捕获屏幕后指针会消失，旧端或原生指针不可用时使用视频指针。Ctrl+Alt+Shift+Esc 释放输入。
- 配对码验证默认关闭，可在 Mac 开启；关闭时仅接收选定接口同子网的连接。每连接随机视频会话、单客户端控制。
- 有界队列，过期 / 丢失帧后请求 IDR，跳过依赖缺失的 P 帧。
- HEVC 不可用时自动重连改用 H.264；断线自动重连；失焦 / 断线释放按键。
- macOS 自动选择已有 IPv4 的雷雳网桥；Windows 从本机 Ethernet 接口广播发现，也可显式指定 IP。
- macOS 圆角卡片界面，区分桌面逻辑尺寸、HiDPI 捕获源像素和最大可用模式，可选择捕获显示器；一次启动申请屏幕录制和辅助功能，自动检查授权，无权限 / 无网桥也能继续设置。
- Windows 圆角卡片和控件，随窗口尺寸 / DPI 调整，可选择目标屏幕并检测原生尺寸、最大可用模式、刷新率和 HDR 状态；中文 / 英文跟随系统，也支持手动切换。
- Windows 保存连接参数；配对码仅在勾选“记住”时使用当前 Windows 用户的 DPAPI 加密保存。
- 两端随系统切换深浅色；Mac 原生语义颜色，Windows 原生标题栏 / 控件主题与高对比度支持。
- macOS 原生登录项与独立系统启动组件：系统 daemon负责发现，LoginWindow agent负责登录界面捕获与输入检查，通过后接受串流，登录后桌面主机接管。登录前实机验收仍待完成；安装不代表已获得系统许可。
- 双向文字与图片剪贴板（UTF-8 / PNG / macOS TIFF / Windows DIB），不传文件。
- Windows ThunderDisplay 系统托盘后台运行，关闭设置不退出；连续断连 3 秒返回设置，新画面恢复后重新打开远程窗口。
- 两端提供安装向导：macOS 原生 PKG、Windows 中文 / 英文安装 EXE，包含升级与自启动配置。Mac 将主应用从“应用程序”拖进废纸篓即可卸载，后台组件约 30 秒后退出并清理；没有独立卸载应用或菜单入口。
- 0.8.18 Windows 码率滑块：左端自动，右端使用实际连接网卡驱动报告的接收速率，无法检测时回退 20 Gbps；保存旧自定义码率，补齐下拉框、展开列表、快捷键输入和滑块的深色显示。两端升级后支持高于 20 Gbps 的请求范围；链路报告值与硬件编码器接受值分别展示。

0.8.20 重写码率滑块的完整绘制，右上角可手填整数 Mbps（精确到 1 Mbps），留空 / 0 选自动；拖动吸附附近整值，间隔随码率增大，方向键不会被吸附锁住。

0.8.21 增加可选无压缩模式，并将多屏鼠标位置与视频分开同步。两端升级后，在 Windows 视频模式选项中选择“无压缩 · 10 位（高速链路）”。该模式保留源像素，码率由尺寸与帧率决定，不使用压缩码率滑块；链路不足时减少完整帧发送，不自动降分辨率、色深或改用编码模式。

0.8.22 修正无压缩传输的固定 1 MiB TCP 缓冲限制，保留系统自动调节；新增完整保留全部 10 位数值的紧密传输，载荷减少 37.5%。新增 TCP 接收窗口、拥塞窗口、重传和排队帧替换诊断，便于区分采集、传输与显示掉帧。旧端继续使用 P010，原编码模式保持兼容。

0.8.23 根据继续掉帧的实机记录，为已认证的 Mac 原始视频连接申请最高 8 MiB 发送缓冲（小帧不超过一帧），避免自动增长停在 4 MiB；Windows 接收与像素还原/上传并行，三个复用缓冲保留最新完整帧。Windows 接收窗口继续自动调节。新增真实队列等待、窗口缩放与采集 complete/idle 状态诊断。

0.8.24 简化 Mac 卸载：移除主菜单、状态栏卸载项和单独的 Uninstaller.app；拖出“应用程序”后自动清理 TD 的启动组件及系统副本，保留废纸篓中的主应用和用户连接偏好。升级会移除旧卸载应用；安装过程暂停移除检测，短时间放回应用会取消清理。

0.8.25 在无压缩模式中仅传输变化区域，基图像按成功传送的帧更新；Windows 先完整还原再取最新图像，跳帧不会漏变化片。新增批量像素还原，保持全部十位值。源率已知且请求达到源刷新率时，采集直接跟随源更新；较低请求仍限制采集频率。当前 60 Hz 虚拟屏的同动画采集对照从约 56 fps 提高至 59.9–60.0 fps；局部动画数据约 0.3 Gbps。模拟 4 Gbps 本机传输验证 60/120 fps 的完整像素一致性，未代替 Windows 实际显示验收。

最新安装包位于 `dist/ThunderDisplay-Mac-Setup-0.8.31-arm64.pkg` 和 `dist/ThunderDisplay-Windows-Setup-0.8.31-x64.exe`。0.8.31 用 ARM 向量指令加速 Mac 十位像素打包，Windows 显示忙碌时重试最新帧，并将窗口重绘和缩放交给显示线程，避免窗口消息线程等待 GPU。新增接收等待、接收调用、线程间隔和慢帧诊断。当前实机日志曾在持续约 60 fps 接收时出现最长 1.067 秒的显示提交阻塞。用户更新 Windows 后，持续动画的 51.48 秒实测接收/上传/显示提交均为 59.888 fps，零队列丢弃或替换，Windows 显示处理最大 0.982 ms，未再出现长时间 Present 阻塞；但最大显示间隔仍为 75.818 ms，并有约 19 MB 大帧的接收等待，不能宣称所有画面都稳定 60 fps。

4096×2560 的当前无压缩十位 4:2:0 格式每个完整帧为 19,660,800 字节；60/120/240 fps 分别需要 9.44/18.87/37.75 Gbps，未计网络开销。此前实测链路约 4.2 Gbps，仅发送变化区域时才可能支持较高帧率；240 fps 平均每帧须低于约 2.19 MB，并同时具备真实 240 fps 采集与显示能力。20 Gbps 即使全部可用也无法承载完整帧的无压缩 240 fps。

0.8.27 将 Windows 无压缩处理延伸到 GPU：按各缓冲和已处理画面的像素块修订记录累计变化，只复制、还原和上传变化区域，再以完整独立 GPU 图像提交显示；跳帧或失败重试不会漏更新。源像素、全部十位值与 SDR 4:2:0 色彩转换保持一致。视频线程采用 Windows 多媒体调度。4096×2560、36 个变化块的本机合成 CPU 对照为 1.630→0.413 ms/帧，GPU 未计入，不能替代 Windows 实机验收。

0.8.29 将 Windows 视频接收缓冲预留移到 TCP 建立连接之前；连接后只扩大应用缓冲不能保证握手时的通告窗口变大。首帧持续收到数据时允许完成（总计最多 60 秒），5 秒无字节进展仍结束连接。接收速率按到达字节计算，首帧未完成也能看到真实带宽。0.8.28 的非阻塞接收和网络线程普通优先级保留；Mac 恢复分段 send，Windows 的精确变化区域和 GPU 上传优化保留。不修改全局 TCP、MTU 或网卡配置。

0.8.26 的 Windows 调试开关继续保留，可在连接中切换，默认关闭并记住选择。新日志自动回传 Mac 的 ~/Library/Logs/ThunderDisplay/windows-client.log，分别记录实际接收、上传与提交显示帧率、最长停顿和各阶段耗时；0.8.27 另记录变化区域处理字节数及真实 GPU 的小型合成自检结果。队列有界、输入优先、每秒最多约 4 KB，不回传屏幕或输入内容。0.8.26 实机两分钟平均接收 60.009 fps、显示提交 59.935 fps，最长间隔 65.567 ms；Windows 0.8.29 与当前 Mac 0.8.27 已实测恢复首帧：19.7 MB 载荷 45.486 ms 收完；随后 141 秒平均成功 Present 59.998 fps，无重连，最长间隔 89.863 ms，仍需单独解决偶发显示停顿。

当前 BetterDisplay 虚拟屏虽配置 240 Hz，独立十位整屏采集仍约 60 fps，另一条整屏接口结果相同；独立窗口约 120 fps。刷新模式、显示时钟回调与真正采集帧率不可等同。BetterDisplay [作者说明](https://github.com/waydabber/BetterDisplay/discussions/4954)高刷新虚拟模式不保证实际生效。本版减少 TD 的处理开销，没有宣称突破当前虚拟屏整桌面的更新限制。

GUI 显示模式仅“自动”和“自定义”，不再提供固定 FPS 档位或帧率输入；帧率取 Mac 当前刷新率与选定 Windows 显示模式检测值的较小值（程序最高 240）。这些帧率是 **请求上限**，不等于已经测得的实际输出。ScreenCaptureKit 的捕获能力、Mac 当前显示模式、编码吞吐量、Windows GPU 和面板刷新率都会影响结果。静止桌面不按目标 FPS 重复发送相同画面，但首次连接和丢包恢复可以从最新捕获表面生成 IDR。自动模式在连接时协商；运行中根据丢包 / 负载动态调整画质尚未实现，CLI 的旧模式别名仅保留兼容，GUI 不显示这些档位。
